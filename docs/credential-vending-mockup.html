新建 Catalog

这里唯一影响「引擎要不要写 AK/SK」的决定是凭据来源。它不是一个开关，而是三种互斥的来源 ——因为「开启」有两种，而「转发长期密钥」在客户端配置上与「签发短期凭据」完全一样， 只有服务端知道区别。
1

基本信息

只影响元数据，与凭据无关

即 REST 客户端里的 warehouse：客户端拿它调 GET /v1/config?warehouse= 换回 prefix。
格式
三个协议面的凭据通道不同：Paimon 走 /token、Iceberg 走 loadTable 的 storage-credentials、Lance 走 describe 的 storage_options。

凭据来源

本页的核心决定 未选择
不下发
只发定位信息（endpoint / region），引擎用自己的身份去读。等价于 stsUnavailable=true。
credentialProviders = []
转发服务端密钥
把配置里的长期 AK/SK 原样发给引擎。今天的默认行为，唯一的优点是能兼容没有 STS 的存储。
s3-secret-key / oss-secret-key
签发短期凭据
服务端拿自己的身份去云上现签，按表路径收窄、读写分离、到期自然失效。
s3-token / oss-token / adls-token …
! 什么都不发，引擎必须有自己的云身份（IRSA / 实例角色 / 节点 AK）。 我们仍然会读文件——服务端自己的 FileIO 用的是部署配置，与这里无关。
accessKeyId
secretAccessKey
只写不读：落库前用 credential-secret-key 加密，服务端从不回显。留空表示保持已保存的那份。
! 这把钥匙没有到期时间。它一旦从引擎容器、日志或 Spark UI 里漏出去，唯一止损办法是轮换密钥并停掉所有作业。 只有在存储不支持 STS（自建 MinIO / Ceph）时才选这一档。

60 分钟
权限范围
写权限要单独给：读请求下发的票不给写。这条不是省事，是把「只读用户拿着票改数据」这条路堵掉。
作用域预览
单表 由表 location 派生，三组路径
别名都指向同一个位置时（abfs / abfss、账户名大小写、尾斜杠） 按一处算；跨账户或跨容器的多路径直接拒绝，而不是悄悄给一张更宽的票。
i 有效期与缓存：服务端在剩余寿命的 15% 处就把条目淘汰（1 小时的票只留 9 分钟）， 命中率下降是刻意的——把快到期的票发给引擎，等于把 403 转嫁给作业。 缓存容量 10000 条，与 Gravitino 的默认值一致。
! 「存储高级参数」里勾了 stsUnavailable=true，表示本存储不提供 STS； 而这里选的是「签发短期凭据」。两者互斥——保存会被服务端拒绝。 要么取消勾选（确认该存储真有 STS），要么改回「转发服务端密钥」。

这一页的六个设计决定

            
            依据见 credential-vending-design.md §10
          

          

            
    
              
  1. 不是「开关 + 参数」，是「三选一 + 参数」。二元开关只能表达「发 / 不发」，而这个决定有两级：发不发是一级，
                发的是长期密钥还是短期票是第二级。把后一级藏进「高级参数」的结果，就是所有人都停在默认值上。
    2. 
              
  2. 客户端配置看不出区别，所以必须在控制台上说清楚。除了「不下发」，另两档在 Spark / Flink 侧一行都不用改
                ——差别全在服务端发的是哪把钥匙。这意味着「配置看起来一样、安全性差一个量级」，唯一的可见性来源就是这里的标记
                和 catalog 列表上的徽标。
    3. 
              
  3. 填了 roleArn 就自动升到签发，并明确告知。这一条抄自 Gravitino 的自动探测：只要 s3-role-arn
                在场，它就用 s3-token 而不是 s3-secret-key。静默升级不行（用户以为还在转发），
                所以我们把「已升级」写在字段下面。
    4. 
              
  4. 有效期给滑块，但按存储标注硬上限。同一个数字在五家云上不是一回事：GCS 的降权令牌 1 小时、
                ADLS 的 SAS 7 天、AWS 在 role chaining 下被压到 1 小时。滑块不拦住不代表不会被云拒绝，
                所以在旁边直接写出来。
    5. 
              
  5. 片段只给到「能被复制粘贴」的程度，不做多引擎的抽象。这些面的键名族完全不同（token.provider=bear
                不是 bearer、Iceberg 的 delegation 头是 header.* 注入、Flink 用 CREATE CATALOG
                而 Spark 用 spark.sql.catalog.*、Lance 要 delimiter=$），
                抽象成一份「通用配置」只会让每一面都跑不起来。
    6. 
              
  6. 「支持某个存储」不等于「三个面都能用」。切到腾讯云 COS 就能看到最极端的一种：同一份配置，
                Paimon 面能用 cosn:// 接到下发凭据、Iceberg 面只能 HadoopFileIO 且收不到凭据、
                Lance 面根本没有 COSN（Rust 侧）得换成 S3 兼容。所以「选存储」不只是换一个 URI 前缀，
                它要连片段生成一起分叉——三面写成一样，等于让两个面静默失败（设计文档 §6.3.2）。
    7.
