Catalogs

catalog 是元数据与数据的命名空间，每个 catalog 指向一处存储位置。名称同时是客户端连接时用的 prefix，创建后不能改名。 执行集群决定这个 catalog 的表存储优化跑在哪个 k8s 集群、用什么身份跑；没配的 catalog 优化调度会被跳过（游标不推进）。

集群与凭据

集群名大小写敏感——它被塞进 x-k8s-aws-id 头
中国区 STS 域名是 sts.cn-north-1.amazonaws.com.cn
必须与 EKS 控制台里逐字一致；写错的表现是 401，不是「找不到集群」。
取自 aws eks describe-cluster --query cluster.certificateAuthority.data
不是秘密，读接口会回显它，用来认「配的是哪把钥匙」。
留空 = 保持原样；要清空得显式勾「清除」。
长期 AK/SK 是这份设计的弱点：建议每个环境一把专用密钥、只授下面那两条权限、90 天轮转。
复制 IAM 最小权限策略（只需两条） 
{
  "Version": "2012-10-17",
  "Statement": [
    { "Effect": "Allow", "Action": "sts:GetCallerIdentity", "Resource": "*" },
    { "Effect": "Allow", "Action": "eks:DescribeCluster",
      "Resource": "arn:aws:eks:ap-northeast-1:123456789012:cluster/prod" }
  ]
}
真正的权限由集群里的 Role / Access Entry 决定；把 IAM 策略放成 AdministratorAccess 不会有任何帮助，只会扩大泄漏面。
ⓘ
AKS 用 AAD 客户端凭据换令牌。scope 必须是 AKS 自己的 audience （6dae42f8-4368-4678-94ff-3960e28e3630）， 不是 management.core.windows.net——用管理面 scope 会得到 401 Invalid audience，看起来像「SP 没授权」。
