# 表详情页（`/tables/:prefix/:database/:table`）

控制台里单张表的操作面。路由三个参数就是 catalog API 的 `{prefix}`、`{database}`、
表名，因此页面上看到的一切与服务端按同一组标识读出的完全一致
——引擎客户端读到的表就是这里显示的表。

整体介绍见 [`console.md`](console.md)，权限判定链见 [`authorization.md`](authorization.md)。

---

## 1. 数据加载：一次进页只发两个请求

打开页面时并发两个请求，结果合成 `overview`：

| 请求 | 用途 | 失败时 |
| --- | --- | --- |
| `GET .../databases/{database}/tables/{table}`（`getTable`） | 表元数据与 schema | 页面显示错误态 |
| `GET .../databases/{database}/tables/{table}/snapshot`（`tableSnapshot`） | 最新快照统计 | 静默降级为 `null`，统计块不渲染 |

第二个请求刻意容错：没有快照的表（还没写入过数据）本来就取不到统计，
把它当错误处理会让一张空表看起来像坏了。

**页签按需加载。** 八个页签里只有四个需要额外请求，切过去才发：

| 页签 | 切过去时的请求 |
| --- | --- |
| 快照 | `listSnapshots` |
| 标签 | `listTags` |
| 分支 | `listBranches` |
| 分区 | `listPartitions` |

「详细信息」「Schema」「变更」「数据访问」只用 `overview` 已有数据，不发请求。
已加载过的页签不重复请求，直到点「刷新」或路由参数变化——`reloadAll()` 清空
已加载标记并重载当前页签。

## 2. 八个页签逐个说明

| 页签 | 数据来源 | 一句话 |
| --- | --- | --- |
| 详细信息 | `getTable` + `tableSnapshot` | **默认页签**：基本信息 + 快照统计 + 表属性 |
| Schema | `getTable` | 字段清单与分区键/主键 |
| 变更 | `alterTable` | 构造一批结构变更后原子提交 |
| 快照 | `listSnapshots` / `getVersionSnapshot` / `rollbackTable` | 版本号查询、详情、回滚 |
| 标签 | `listTags` / `createTag` / `dropTag` / `rollbackTable` | 把某个快照固定下来 |
| 分支 | `listBranches` / `createBranch` / `renameBranch` / `forwardBranch` / `dropBranch` | 可写的历史线 |
| 分区 | `listPartitions` | 分区级活跃数据统计 |
| 数据访问 | `getTableToken` / `authTableQuery` | 临时凭据与查询级授权规则 |

### 2.1 详细信息

页面的默认落点，回答「这是一张什么表」：表 ID、是否外部表、Schema 版本、路径、
Owner、创建与更新（时间 + 操作者）、四张统计卡片（记录数 / 数据文件数 / 数据文件大小 /
最近文件写入），以及表属性（`options`）的只读 JSON。

把它单独做成一个页签、并作为默认页签，是因为原来的布局把这部分常驻在页头下方，
既挤压了页签内容，又让「概览」与「细看」混在一起。现在打开表先看到全貌，
要动结构再去「变更」，要改属性去「变更」页签的 `setOption`。

表属性（`options`）只在这里展示，Schema 页签不再重复渲染一次 JSON。

### 2.2 Schema

字段表（ID / 字段名 / 类型 / 注释 / 默认值）加分区键、主键、表注释三项。
类型是判别联合，页面按原样显示而不做归一化——显示成前端理解的形状会掩盖服务端实际存的值。

### 2.3 变更

不是「读一个改动列表」，而是**构造器**：从 10 个动作里选一个、填字段、点「添加」，
攒够一批后一次性提交。表单能在前端拦住的必填项（除「可选」标注与注释类字段）先拦一道，
不留到服务端报 400。动作值与提交字段的映射集中在 `toChange()` 一处，
由 `scripts/verify-console.py` 第 8 组与规格的 `SchemaChange` 逐字段比对。
细节见 [`console.md` §4.1](console.md#41-变更构造器)。

### 2.4 快照

列出全部快照（版本 / 快照 ID / 提交类型 / 提交者 / 提交时间 / 总记录数 / 增量记录数），
支持按版本号直查某一版、抽屉里看原始 JSON、以及回滚。

回滚确认框写清两件事，因为它们最容易被误解：

- 目标快照**之后**的提交记录会被删除，无法恢复；
- 回滚只移动指针，**不回收数据文件**——它们变成不再被引用的孤儿文件。

页面另外提示：若有客户端正在写入这张表，回滚前应先停止写入。

### 2.5 标签

标签把快照固定下来，使其不受快照过期清理影响。新建时可指定标签名、目标快照 ID
（留空表示最新）、保留时长（如 `7d` / `12h`）与「已存在时忽略」。
回滚到标签与回滚到快照是同一个端点（`rollbackTable` 的 `instant` 判别联合），
差别只在 `type` 是 `tag` 还是 `snapshot`。删除标签后该快照即失去保护。

### 2.6 分支

分支是可写的历史线，常用于隔离试验或并发写入。列表不含主分支。
支持新建（可从某个标签起）、重命名、推进到主分支最新快照、删除。
推进会让该分支上的独立提交变成不可达历史，因此确认框明确写出这一点。

### 2.7 分区

分区级统计的口径是**最新快照引用的文件**，因此各分区之和可能小于仓库实际占用
——历史文件与未被最新快照引用的文件不计入。页面用一条提示写明这个口径，
避免把「和小于总量」当成数据丢失。

### 2.8 为什么没有权限页签

**授权不在这张表上做。** 表级权限统一到「权限管理」页（`/permissions`）：那里把
作用范围选成 Table 或 View、选好库与对象，就能看到并撤销作用在这张表上的每一条授权，
四级资源（catalog / database / table / view）共用一套表单与一份清单。

此前这一页有过一个「权限」页签，它列的是 catalog 角色携带的授权，并与「权限管理」页
的直接授权分属两个模型、两份清单——同一件事要看两处、撤两遍。现在
Polaris 的 RBAC 面退出控制台（管理面留在管理 API 与 Spark SQL），这一页随之消失，
顺带省掉了它最贵的成本：管理规格没有「按资源反查授权」的端点，那个页签要
先列全部 catalog 角色、再逐个取回 grants 后在控制台侧过滤（N+1 个请求，
且随角色数线性增长）。完整的作用范围与判定顺序见
[`authorization.md`](authorization.md)。

### 2.9 数据访问

两个只读工具：

- **数据访问令牌**（`getTableToken`）：服务端按 catalog 的存储配置下发临时凭据。
  以 `paimon.rest.credential-manager.type=noop` 运行时返回 501，页面如实显示
  ——那种部署下由引擎自带的云凭据链负责鉴权。
- **查询级授权规则**（`authTableQuery`）：传入要查询的列，服务端按调用主体的授权
  返回行过滤表达式与列脱敏规则。两者都在引擎侧生效，控制台只负责展示服务端给出了什么。

## 3. 破坏性操作

全部走统一的危险确认框（标题 + 目标 + 后果说明），没有「一键直达」的路径：

| 操作 | 后果 |
| --- | --- |
| 回滚到快照 / 标签 | 其后的提交记录被删除，数据文件不回收 |
| 删除标签 | 该快照失去保护，快照过期时可能被清理 |
| 推进分支 | 分支上的独立提交变为不可达 |
| 删除分支 | 只删指针，快照是否保留取决于是否另有标签引用 |
| 删除表 | 元数据与快照历史移除，**数据文件不会自动清理** |

删除表成功后跳回目录浏览页，并保留当前 catalog 与 database 作为查询参数。

页头另有「返回列表」与「刷新」。刷新重载 overview 与当前页签，不重置到默认页签。

## 4. 校验与测试

`scripts/verify-console.py` 有三组直接盯着这个页面：

| 组 | 守什么 |
| --- | --- |
| 8. 变更构造器 | `toChange()` 能提交的动作与字段都在规格的 `SchemaChange` 里有定义 |
| 9. 对话框状态 | 本页两个 `el-dialog`（新建标签、新建分支）都声明了 `destroy-on-close`，否则编辑会残留上一次的取值；快照详情是抽屉，不受这一组约束 |
| 10. 下拉候选来源 | 页面上的 `el-select` 都必须有 `el-option`/`:options` 之类的候选来源；确属自由输入的（如命名空间）要在源码里写 `el-select-free-input` 标记显式豁免 |

服务端侧 `ConsoleApiTests` 守住静态资源与深链回退。三组守卫都做过**变异测试**：
把修复临时改回去，确认对应用例真的失败，而不是空跑。

## 5. 已知边界

- **不做写入**：不提供 `commitTable`——控制台拼不出一个指向真实文件的快照，
  理由见 [`console.md` §7](console.md#7-端点的取舍为什么没有-committable)。
  本页对快照的介入只有「读」与「回滚」。
- **按表 ID 定位不在这里**：那条路径在目录浏览页（`/browse`），因为它不需要先知道库名。
- **表属性只查看**：`options` 的读写在「详细信息」（只读）与「变更」页签的
  `setOption` / `removeOption`（写入）两处，本页没有单独的属性编辑器。
